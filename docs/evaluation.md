# FDE 智能风控 Agent 效果评测报告

> 版本：v1.0　|　日期：2026-10-03　|　评测对象：FDE 智能采购风控 Agent（fde-agents）
> 评测集：`fde-agents/evaluation/dataset.json`　|　脚本：`fde-agents/evaluation/run_evaluation.py`
> 结果：`fde-agents/evaluation/report_local.json`（规则引擎直调）、`report_api.json`（HTTP 全链路）

## 一、评测目的

FDE 智能风控 Agent 负责对采购申请执行风险分析、供应商尽调与审批建议，是采购审批路由（自动通过 / 人工审批）的决策大脑。本评测通过**人工标注评测集 + 批量跑批**的方式，量化评估 Agent 在风险分级、评分精度与审批建议三个层面的效果，验证：

1. 规则引擎输出是否符合方案 5.1 风控规则（金额阶梯、风险维度、阈值）；
2. 完整 Agent 链路（Supervisor 编排：风险分析 → 供应商尽调 → 审批建议）是否与标注预期一致；
3. 是否存在误杀（低风险被误判为中/高风险）等安全敏感问题。

## 二、评测方法

### 2.1 评测集设计

`dataset.json` 共 **25 条标注样本**，输入为采购单风险画像（与 ERP `_build_payload` 构造的上下文一致）：

| 字段 | 含义 |
| --- | --- |
| `total_amount` | 采购总金额（CNY） |
| `first_cooperation` | 是否首次合作供应商 |
| `supplier_risk` | 供应商档案风险等级偏高 |
| `category_mismatch` | 采购品类与部门历史不符 |
| `frequency_risk` | 同一供应商短期内多次采购 |
| `over_budget` | 是否超出部门预算 |
| `supplier_name` / `supplier_id` | 供应商上下文（避免"未知供应商"系统性误判，贴近真实采购单） |

每条样本给出三档预期值：**预期风险等级**（low / medium / high）、**预期评分区间**（精确到分值，用于校验规则打分）、**预期审批建议**（approve / human）。

样本覆盖策略：

- **低风险档（6 条）**：常规小额采购、金额阈值下方边界（4.9 万）、低风险但触发单一维度的组合（4.9 万+新供应商=25 分仍自动通过）；
- **中风险档（11 条）**：金额阶梯各段（5 万=30 / 20 万=45 / 50 万与百万=60）、单维度组合（5 万+新供应商=55、5 万+品类=50、5 万+频次=45、5 万+超预算=50）、恰好中风险边界（4.9 万+新供应商+频次=40）、多维度（3 万+新+风+频=65）；
- **高风险档（8 条）**：恰好高风险边界（20 万+新供应商=70、5 万+新+超=75）、大额组合（50 万+新=85、49 万+新+风=95、19.9 万+新+风=80）、满分维度组合（5 万全维度=100、3 万全维度=105）。

边界值（50k / 200k / 500k 金额阶梯、40 / 70 阈值）均设专门样本，用于验证临界判断。

### 2.2 指标定义

| 指标 | 定义 | 计算公式 |
| --- | --- | --- |
| 风险分级命中率 | 预测风险等级与标注一致的样本占比 | 分级正确数 / 总样本 |
| 评分命中率 | 预测风险分落在标注评分区间的样本占比 | 评分正确数 / 总样本 |
| 审批决策一致率 | 预测审批建议与标注一致的样本占比 | 决策一致数 / 总样本 |
| 综合准确率 | 分级、评分、决策三者全对的样本占比 | 全对数 / 总样本 |
| 误杀率 | 标注为低风险却被判为中/高风险的样本占比 | 误杀数 / 低风险样本数 |

### 2.3 两种评测模式

脚本支持双模式，结果相互印证：

- **local 模式**（`--mode local`）：直接调用 `app.services.risk_rules.compute_rule_score` + 审批建议规则兜底（阈值 40/70），验证规则引擎自身，不依赖网络与服务，可离线复现；
- **api 模式**（`--mode api`）：通过 HTTP 调用 `http://127.0.0.1:8001/analyze`，走完整 Supervisor 链路（风险分析 → 供应商尽调 → 审批建议），验证全链路一致性；请求失败自动重试 2 次。

## 三、评测结果

### 3.1 汇总指标（2026-10-03 实跑）

| 指标 | local 模式 | api 模式 |
| --- | --- | --- |
| 样本总数 | 25 | 25 |
| 风险分级命中率 | **100%** | **100%** |
| 评分命中率 | **100%** | **100%** |
| 审批决策一致率 | **100%** | **100%** |
| 综合准确率 | **100%** | **100%** |
| 误杀率 | **0%** | **0%** |

样本分布：低风险 6 条、中风险 11 条、高风险 8 条；预测分布与标注完全一致。

### 3.2 规则引擎（local）逐条结论

25 条全部命中标注，规则打分精确到分值一致。关键边界样本验证通过：

- 4.9 万（<50k 金额段）→ 0 分 low / approve；5 万（≥50k）→ +30 分；
- 19.9 万（<200k）→ 金额 30 分；20 万（≥200k）→ 45 分；49 万→45 分；50 万（≥500k）→ 60 分；
- 40 分恰好中风险（4.9 万+新+频）；70 分恰好高风险（20 万+新）；75/80/85/95/100/105 组合均正确归类。

### 3.3 全链路（api）逐条结论

25 条全部命中标注。过程中发现并处理了两类输入/运行问题：

1. **未知供应商误判**：初版评测集未带供应商上下文时，全链路尽调子图对"未知供应商"生成风险信号，将 2 条低风险样本判为 human（0 分、25 分）。补充正常供应商上下文后消失。**结论：这是 Agent 对信息缺失的保护性兜底（属预期行为），评测集须模拟真实采购单上下文。**
2. **偶发异常响应**：批量跑批时个别样本出现返回缺失（评分 0/等级 low），单条重放正常；脚本增加失败重试后稳定。**结论：全链路含 LLM/网络调用，跑批需容错重试。**

## 四、结论与建议

### 4.1 结论

1. **规则引擎达到设计预期**：金额阶梯（30/45/60）、六维度加分、40/70 双阈值实现与方案完全一致，打分精确、分级无误、无低风险误杀；
2. **全链路与规则引擎一致**：Supervisor 编排下，评分、分级与审批建议与规则兜底保持一致，尽调信号仅作为补充保护（对未知供应商倾向人工复核），未破坏低风险自动通过主路径；
3. **决策安全性良好**：误杀率 0%，所有低风险样本均正确自动通过；高风险样本全部转人工，符合"风险高必须人工"的管控要求。

### 4.2 局限与后续建议

| 局限 | 说明 | 建议 |
| --- | --- | --- |
| 评测集规模 | 25 条标注样本，覆盖规则全维度但业务多样性有限 | 后续从真实审批流水抽取样本扩充到 100+，覆盖真实分布 |
| 全链路 LLM 波动 | 配置 LLM Key 后决策可能受模型输出影响，存在偶发不一致 | 建立基线快照，定期回归；对决策偏差设置告警 |
| 评测输入为画像快照 | 未验证 ERP→FDE 传输层字段映射 | 增加端到端用例：从 ERP 提交采购单到 FDE 返回全链路比对 |
| 边界外推 | 超大金额（千万级）、多维度极端组合仅靠规则叠加 | 补充高压场景用例，评估是否需要金额阶梯上限封顶 |

## 五、复现方式

```bash
cd fde-agents
# 规则引擎直调（离线可复现）
PYTHONPATH=. python evaluation/run_evaluation.py --mode local
# 全链路 HTTP（需 fde-agents 8001 服务运行）
PYTHONPATH=. python evaluation/run_evaluation.py --mode api
```

产物：`evaluation/dataset.json`（评测集）、`evaluation/run_evaluation.py`（脚本）、`evaluation/report_local.json` / `report_api.json`（结构化结果）。
